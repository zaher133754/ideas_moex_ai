# Scout Trading

Telegram-бот ищет свежие идеи российского рынка через **установленный Codex CLI**. Два отдельных запуска: поиск кандидатов и критическая проверка источников/расчётов. Программа загружает котировки Мосбиржи, проверяет применимость уровней, рассчитывает рейтинг и отправляет топ‑3 каждый день в **09:00 Europe/Samara (UTC+4)**. Файлы с подробным разбором до 5 и до 10 идей доступны по кнопкам и командам.

Поддерживаются акции, облигации/ОФЗ, фонды, фьючерсы, лонги, шорты, идеи с плечом и арбитражные корзины из 2–4 инструментов. Работа через Codex с сохранённой авторизацией ChatGPT; отдельный OpenAI API в коде не используется. Лимиты/доступность модели определяются аккаунтом Codex. Сделки бот не совершает.

## Быстрый запуск

Нужны Python ≥3.12, `uv`, Codex CLI с поддержкой `exec --ignore-user-config --output-schema --json`, доступ к Telegram, OpenAI и MOEX ISS. Проверенная локальная версия CLI: 0.161.0.

```powershell
uv sync --frozen
Copy-Item .env.example .env
# Заполните .env в редакторе, токен не отправляйте в чат.
codex login
uv run scout doctor
# Реальная доставка тестового сообщения и HTML-файлов с обратным скачиванием/сравнением.
# Не помечает утренний выпуск отправленным и не создаёт вымышленных сделок.
uv run scout selftest
uv run scout bot
```

Linux: `cp .env.example .env`, `chmod 600 .env`; остальные команды аналогичны. CLI `codex` должен быть исполняемым файлом. На Windows при установке через npm задайте `CODEX_BIN` путём к нативному `codex.exe`, поскольку запуск `.cmd` через shell намеренно запрещён.

1. Создайте бота у **@BotFather**, поместите токен в `TELEGRAM_BOT_TOKEN`.
2. Укажите свой числовой Telegram user ID в `TELEGRAM_OWNER_ID`. Узнать ID можно через **@userinfobot** или свои данные Telegram. `TELEGRAM_CHAT_ID` можно оставить пустым: личный чат определяется после `/start`.
3. Запустите бота и отправьте ему `/start`. Telegram запрещает боту начинать личную переписку до этого шага.
4. Используйте `/search`, затем `/today`. Для работающей ежедневной рассылки процесс должен постоянно работать на сервере.

Настройки не печатают токены. Файлы `.env`, данные авторизации Codex и `data/` не включаются в git. Доступ к командам и скачиванию файлов получает только `TELEGRAM_OWNER_ID`; для группы дополнительно требуется явно задать `TELEGRAM_CHAT_ID`.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Подключить личный чат, показать команды |
| `/today` | Показать последний подготовленный выпуск с его фактической датой |
| `/search` | Подготовить сегодняшние идеи; повторный поиск после отправки выпуска запрещён |
| `/report5` | Скачать HTML с подробным разбором до 5 идей |
| `/report10` | Скачать HTML с подробным разбором до 10 идей |
| `/status` | Время, расписание, состояние поиска и доставки |
| `/retry` | Повторить неудачную/неподтверждённую доставку сегодняшнего выпуска |

HTML — автономный файл, открывается в браузере без интернета. Markdown и JSON также сохраняются в `DATA_DIR/reports/`. HTML экранирует текст агента, не содержит JavaScript и внешних ресурсов.

```powershell
# Проверка авторизации CLI и реального получения котировок; Telegram не требуется.
uv run scout doctor
# Реальное исследование и локальные файлы; сообщения в Telegram не отправляет.
uv run scout research
# Повторный экспорт уже сохранённого отчёта.
uv run scout export
# Проверки разработки.
uv run pytest -q
uv run ruff check .
```

`research` и бот используют одну блокировку процесса: одновременно с работающим ботом используйте `/search`. Это предотвращает конкурирующие исследования и отправки.

## Локальная проверка на Windows

После заполнения `.env` можно оставить бота в фоне без открытого терминала:

```powershell
# Только запуск:
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File deploy/windows-start.ps1
# Запуск с немедленным реальным поиском, сообщением и файлом владельцу:
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File deploy/windows-start.ps1 -ResearchNow
# Остановить только процессы бота из этого проекта:
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File deploy/windows-stop.ps1
```

Это локальный запуск без установки автозапуска Windows. Компьютер должен работать и иметь доступ в интернет; после перезагрузки бот запускается снова вручную. Серверная установка описана ниже. `/search` присылает готовую подборку с кнопками файлов сразу после проверки.

Журнал с ротацией: `DATA_DIR/logs/scout.log`. Токен маскируется в сообщениях и исключениях. Скрипт запуска дополнительно сохраняет вывод в `data/logs/launcher.stdout.log` и `launcher.stderr.log`. Состояние процесса и время последнего обновления сохраняются в SQLite (`kv.runtime`) каждые 5 секунд. Результат последней проверки доставки: `DATA_DIR/diagnostics/last-selftest.json`.

## Расписание и восстановление

- **08:00 Самара:** начинается поиск, затем отдельная оценка кандидатов. Таймаут каждого запуска Codex — 15 минут. Если открытие страниц в Codex недоступно, программа читает публичные публикации с разрешённых доменов и повторяет поиск с их содержимым; полный цикл включает до трёх запусков CLI.
- **08:57:** обновляются котировки и заново проверяются входы/стопы/цели. Арбитраж с изменившимися ценами отбрасывается, если нужна новая оценка.
- **09:00:** отправляется сообщение с топ‑3 и кнопками файлов. При нормальной работе и готовом отчёте запуск отправки происходит с точностью около секунды; задержка доставки зависит от Telegram/сети.
- Если отчёт не готов к 09:00, приходит сообщение о задержке. Поиск повторяется до трёх раз, результат отправляется после завершения, до 12:00. Вчерашний выпуск не используется вместо сегодняшнего.
- После перезапуска сервис восстанавливает состояние из SQLite. Автоматически догоняет только текущий выпуск до 12:00; старые дни не рассылает. Работа ежедневно, включая выходные: без свежих подходящих материалов приходит сообщение об отсутствии идей.
- Ручной отчёт, подготовленный ночью до начала утреннего поиска, не заменяет утреннее исследование: в 08:00 поиск проводится заново. Обновление котировок сохраняет отдельное время исходного исследования.
- После подтверждённой доставки тот же дневной выпуск автоматически не повторяется. При сетевом таймауте результат доставки может быть неизвестен: Telegram не поддерживает ключ идемпотентности. Состояние `uncertain`/`sending` требует проверить чат и выполнить `/retry` при необходимости. Слепого автоматического повторения нет; `/retry` при уже принятом Telegram сообщении может создать дубль.

## Отбор и рейтинг

Свежесть — по **дате публикации**, а не по дате поиска/индексации. Минимум один непосредственно поддерживающий идею источник за последние `FRESH_HOURS=48` часов. Более старые первичные документы разрешены как дополнительные доказательства. Для страниц без времени агент должен использовать начало дня издателя — консервативную границу. Даты и их обоснование входят в файл.

Проверки программы: срок применимости, прошедший катализатор, возраст котировки, минимальный оборот, режим торгов и единицы цены, расстояние до входа, стоп, уже достигнутые цели, погашение/экспирация, доход/риск после заданной комиссии. Перед отправкой проверки повторяются.

У одиночной идеи по акции/фонду/фьючерсу обязателен стоп и минимум одна цель. Свежая событийная публикация может не содержать торговых уровней: поисковый агент возвращает их как `null`, программа получает свечи MOEX, а второй агент может предложить условный план на их основе. В разборе он обязан отличать собственные уровни от опубликованных автором. Инструменты, направления и размеры сторон менять нельзя. Без подтверждённого окончательного плана идея не попадёт в рейтинг.

Доход/риск рассчитывается по худшей границе входа и ближайшей цели с двусторонней комиссией; порог 1.5. Это сценарное отношение, стоп не гарантирует цену исполнения. Для покупки облигации допустим сценарный выход без ценового стопа: нужны параметры выпуска и подтверждённая доходность. Цены облигаций — процент номинала; файл показывает номинал, НКД и стоимость бумаги с НКД, когда они доступны.

Для арбитража нужны свежие синхронные bid/ask обеих сторон и последние сделки, расчёт одной корзины, капитал, сценарный убыток, условия исполнения и прочие расходы. Комиссия рассчитывается на вход и выход **каждой стороны**, переводится в б.п. относительно капитала корзины. Для фьючерсов стоимость точки переводится в рубли через шаг цены. Отсутствие исполнимых котировок, устаревший стакан и отрицательная премия после расходов исключают идею. Поэтому перед открытием отдельных рынков арбитражные идеи могут не пройти отбор.

| Компонент | Максимум |
|---|---:|
| Подтверждённые доказательства — оценка второго агента | 25 |
| Логика тезиса — оценка второго агента | 20 |
| Контроль риска — оценка второго агента | 15 |
| Реалистичность исполнения — оценка второго агента | 10 |
| Ликвидность по обороту MOEX | 10 |
| Свежесть поддерживающего источника | 10 |
| Доход/риск или качество сценарного ограничения риска | 10 |

Рейтинг 0–100 **не является вероятностью прибыли**. Порог по умолчанию 65. В файле видны компоненты, аргументы и недостатки. Если проходят 0–2 или меньше 5–10 идей, показывается фактическое количество, квота не заполняется.

Дедупликация хранит историю всех идей доступного расширенного выпуска после его подтверждённой доставки: по инструментам/направлению, устойчивому ключу события, совпадению источников и сходству тезиса. Технический паттерн не становится новым из-за нового заголовка или небольшого изменения уровней. История по умолчанию 90 дней. Материально другое событие по тому же активу допустимо. Семантический отбор дополняется заданием агенту; стопроцентной защиты от перефразированных повторов эта эвристика не даёт.

## Настройки и границы проверки

Все параметры — в [.env.example](.env.example). `ALLOW_SHORTS=true`, `ALLOW_FUTURES=true`, `MAX_IDEA_LEVERAGE=5` — начальные значения; лимит плеча меняется. `COMMISSION_BPS=5` — **пример для расчёта**, замените на свои условия. Для фьючерсов реальные комиссии часто задаются за контракт, поэтому единая оценка bps является приближением; второй агент должен учитывать прочие биржевые/брокерские расходы отдельно в арбитражных расчётах.

Агент проверяет публикации и обоснование уровней через веб-поиск; программа самостоятельно не доказывает их истинность и не пересчитывает полную финансовую модель. Недоступный источник должен приводить к отказу второго агента. Ограничения займа, доступное ГО, стоимость фондирования и налоги конкретного пользователя не доступны без брокерских данных: в идее они остаются обязательными условиями перед исполнением. Дневной оборот не доказывает глубину стакана для вашего объёма.

MOEX ISS может отдавать задержанные цены. При отсутствии текущих сделок берётся последняя дневная сессия с её датой (время 00:00 означает, что точное время закрытия неизвестно). Котировка ограничивается `QUOTE_MAX_HOURS=96` для выходных; публикации всё равно ограничены 48 часами. Сейчас поддерживаются рублёвые биржевые режимы TQBR/TQTF/TQCB/TQOB и RFUD. Валютные облигации, OTC, опционы и торговые режимы иных площадок требуют отдельных адаптеров и в текущей версии отбрасываются.

Журналы Codex с запросами и источниками сохраняются в `DATA_DIR/runs/`; ограничьте доступ к каталогу и хранение по своей политике. Исследователь запускается с live-поиском, без shell, приложений, MCP, hooks, пользовательского конфига, субагентов и токена Telegram в окружении. Бот не даёт исследователю выполнять команды или отправлять сообщения.

Резервное HTTP-чтение ограничено списком публичных финансовых доменов в `scout/sources.py`: только HTTPS, проверка публичного DNS, каждый редирект проходит проверку, ограничены время/размер, запрещены URL с учётными данными и локальные адреса. Ответы 401/403 и закрытые платные материалы не читаются. Из HTML извлекаются открытый текст и кандидаты дат публикации из meta/time/JSON-LD; агент должен проверить, относятся ли они к основной статье. Можно расширить список проверенных доменов в коде.

## Ubuntu-сервер

Подготовлен [deploy/install.sh](deploy/install.sh) и [systemd unit](deploy/scout-trading.service). Установка предполагает Ubuntu 24.04+ и права root; установщик создаёт отдельного пользователя `scout`, каталог `/opt/scout-trading`, состояние `/var/lib/scout`, настройки `/etc/scout-trading/env`. Авторизация Codex выполняется **под тем же пользователем, что сервис**.

```bash
# Скопируйте исходники на сервер (без .env, .venv, data и авторизации Codex).
sudo bash deploy/install.sh
sudoedit /etc/scout-trading/env
# TELEGRAM_BOT_TOKEN, TELEGRAM_OWNER_ID; DATA_DIR уже задан установщиком.
sudo -u scout env HOME=/var/lib/scout CODEX_HOME=/var/lib/scout/.codex codex login --device-auth
sudo -u scout env HOME=/var/lib/scout CODEX_HOME=/var/lib/scout/.codex \
  /opt/scout-trading/.venv/bin/python -m scout doctor --env-file /etc/scout-trading/env
sudo systemctl enable --now scout-trading
sudo journalctl -u scout-trading -f
```

Отправьте `/start` боту. Авторизация ChatGPT может истечь/потребовать повторного входа; `doctor` проверяет её наличие, но не гарантирует доступ к модели. Серверу нужен исходящий HTTPS, веб-сервер, публичный порт и домен не требуются: используется Telegram long polling.

Для обновления кода: остановите сервис, обновите исходники в `/opt/scout-trading`, выполните `.venv/bin/pip install --no-deps .`, запустите сервис. Не удаляйте `/var/lib/scout`: там история повторов, состояния доставки и авторизация.

Основания интеграций: [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [live web search](https://learn.chatgpt.com/docs/config-file/config-basic), [Telegram Bot API](https://core.telegram.org/bots/api), [MOEX ISS](https://iss.moex.com/iss/reference/).
